# TC file format

Headings, field names and fixed values follow `<plugin>/kit/artifact-labels.mjs` for the configured `locale`; this page shows the `en` labels.

Shared standard read by the e2e-test batch parser, `tdd-implement` (unit targets, owners) and `coverage-gate` (G2, G3a, G3). `####` sub-section names and the **bold** metadata field names are parse keys — keep them exact. Do not add values to enumerations (`E2E suitability`, checkpoint `Type`); add rows instead, which the parsers ignore safely.

## File header

```markdown
# <Feature name> Test Cases

> **Created**: YYYY-MM-DD
> **Scope**: <screen > component>
> **Related files**: <comma-separated paths analysed> (new mode: planned files prefixed `(new)`)
> **PRD**: <prd path>
> **TC count**: N          (new mode: `N (unit N · e2e N · manual N)`)
> **Implementation mode**: new    ← new mode only; its presence is what marks new mode
> **Generated by**: /dev-pipeline:tc-extract
```

Then `## Overview` (2–4 sentences), `## Acceptance Criteria` (the PRD's `- [ ] **AC-NN**:` list), `## Test Cases`.

## One TC = `### TC-NN: <name>` + 7 fixed sub-sections + 2 optional (`Notes`; `Unit checkpoints` when the unit target is set)

Each TC ends with a `---` line.

### `#### Metadata` — 13-row, 2-column table (`| Field | Value |`)

| Field | Allowed values | Consumer |
|---|---|---|
| **TC ID** | `TC-01` | — |
| **Spec file** | `<e2e.specFilePrefix>tc01-<kebab>.spec.js`, or `(none)` for unit-only TCs | e2e-test batch: output file name |
| **Priority** | `High` / `Medium` / `Low` | — |
| **Type** | `happy path` / `error handling` / `ui` / `boundary` / `regression` | — |
| **Related AC** | `AC-01, AC-02` | `coverage-gate` AC coverage; a TC without this row is `no-related-ac` |
| **E2E suitability** | `e2e` / `manual` | `manual` TCs go to `## Manual review items` and are skipped by e2e-test |
| **E2E basis** | required for `e2e`: one line naming focus or navigation result · rendered DOM · observed host request · page transition / reload / restore round trip. `—` for `manual` | `coverage-gate --lint` blocks an `e2e` TC without it. A basis that is a branch decision, a computation or a contract belongs to the unit layer |
| **Screen** | free text (page or feature area) | report `screen`; screen-context lookup |
| **Start URL** | path or `/` | `START_URL` |
| **Fixtures** | comma-separated file names in `e2e.fixturesDir`, or `(none — live API)` | `mockAll` route map |
| **AI verdict** | `PASS only` / `WARNING allowed` | not read for the verdict: it is rule-based `PASS` / `FAIL` |
| **Console error whitelist** | `(none)` or comma-separated substrings | `CONSOLE_ERROR_WHITELIST` |
| **Unit target** | `(none)` or a repo-relative test file path | tdd-implement: becomes the plan task's `Test:` line |

`Unit target` is orthogonal to `E2E suitability`: all four combinations are valid and **a TC is never split** to separate them. It holds a path, not a boolean, so the plan never invents file names.

### `#### Preconditions`

Bullets. API mocks as `**API mock**: <url glob> → <fixture file>`, one per line. Globs are Playwright globs and end with `*` when the request carries a query string (`**/api/items*`) — copy the shape existing specs use. List the boot fixtures (`e2e.bootFixtures`) the `fixture-advisor` agent names even when the TC does not exercise them; an isolated run cannot boot without them. Also login state and data prerequisites. Nothing → `- none`.

### `#### Entry path`

Numbered steps in the entry-path DSL (below). Each step: inline code, then ` — ` and a short purpose.

### `#### Render-ready condition`

Three fixed bullets:

- **Method**: `waitFor selector` / `waitFor expr` / `app ready only`
- **Expression**: a CSS selector (goes to the assembler's `renderSelector`) or a JS boolean (`readyExpr`) — `N/A` when app ready only
- **Timeout**: `<ms>` — `N/A` when app ready only

### `#### Checkpoints`

5-column table, ids `CP-01`, `CP-02`, … Each row becomes one `SUCCESS_CRITERIA` entry and one `cp()` assertion in the spec.

| CP ID | Type | Target / Path | Condition | Description |
|-------|------|---------------|-----------|-------------|

Write a `|` inside a cell as `\|`; the gates do not read the escaped form as a column boundary.

**Types** — exactly these seven (`ko` labels in brackets). Any other value stops the assembler.

| Type | Target / Path | Condition |
|---|---|---|
| `DOM` | target descriptor: bare CSS (`.list-item`), `css:<sel>`, `testid:<value>`, `role:<role>[<name>]`, `text:<text>` | `visible` (default) · `hidden` · `hasText('…')` · `not hasText('…')` · `not hasClass <class>` · a Playwright locator matcher written out: `toHaveCount(N)`, `toHaveAttribute('k', 'v')`, `not.toBeVisible()` … |
| `Focus` (`포커스`) | informational (`focus`); the value read is config `ui.stateBridge.focusExpr`, or the focused element's opening tag when unset | `includes('…')` · a matcher call (`toBe('…')`) |
| `State` (`Store`) | `<store>.<field.path>` under `ui.stateBridge.globalExpr` — only when the bridge is configured | `truthy` · `falsy` · `exists` (not null) · `matches /re/` · a matcher call (`toBe('…')`, `toEqual(…)`, `toHaveLength(N)`) |
| `Runtime` (`런타임`) | `consoleErrors` / `networkErrors` | `isEmpty` · `filteredCount < N` |
| `URL` | `pathname` / `search` / `href` | `hasText('…')` · `not hasText('…')` · `exists` · `matches /re/` · a matcher call (`toBe('/path')`) |
| `Popup` (`팝업`) | `count` (windows opened) / `url` (first window's address) | `count`: a matcher call, default `toBe(1)` · `url`: `hasText('…')` · `not hasText('…')` · `matches /re/` |
| `Observe` (`관측`) | CSS selector of a short-lived element (toast) | `peak <matcher>` (most copies seen at once, e.g. `peak toBe(1)`) · `texts hasText('…')` · `texts not hasText('…')` (text seen) |

- `hasText` is a substring match everywhere.
- **Retired forms stop the assembler** with `unknown checkpoint condition`: `count(N)`, `length(N)`, `hasClass('…')`, `noConsoleErrors`, and call-shaped Focus conditions other than `includes(…)` and matcher calls (`matches('<css>')`, `hasText('…')`, `not hasText('…')`). Write `toHaveCount(N)`, `toHaveLength(N)`, `toHaveClass(/…/)`, `isEmpty`, `includes('…')`.
- **Focus** takes plain text that is not call-shaped as a literal substring of the focus value.
- `Observe` samples every 250 ms from before the interaction (across reloads) because checking the DOM once cannot tell "never shown" from "shown and gone". The window is 3 s after the interaction; for longer write `observe Ns` (`ko`: `관측 N초`) in the description. One window per TC: the first Observe row's window applies to every Observe row. An Observe row cannot be a before-interaction checkpoint.
- A checkpoint on the state **before** the interaction starts its description with `[before]` (`ko`: `[조작 전]`); the assembler places it ahead of the interaction.
- A landing checkpoint asserts the value that decides the destination (an id, a menu key), with `pathname` or `search`. A regex on the path prefix also passes `/menu/undefined`. `coverage-gate --tc --lint` blocks `href` contains-assertions and `search` contains-assertions without the parameter name — write `search hasText('id=42')`, not `hasText('42')`.
- When code cannot settle the expected value (it depends on a server answer), append `[verify: <what>]` to the description and write your best value. The assertion stays hard; the report lists the checkpoint with its actual value for review.

Values come from code that was actually read. Unconfirmed entries carry `[verify: selector not found]` / `[verify: state path not found]`. In new mode, predicted values carry a `(new)` suffix.

### `#### Success criteria`

`> ` blockquote, 1–3 sentences in user language covering all checkpoints. Passed verbatim as the spec's `successCriteriaText`.

### `#### Expected results`

Numbered list, each `<result> — CP-NN`, about one per checkpoint.

### `#### Notes` *(optional; omit when empty)*

Known behaviours, soft-pass conditions, environment dependencies. New mode must include:

`> Predicted selectors for new implementation — verify after implementing`

### `#### Unit checkpoints` *(only when Unit target ≠ (none))*

| UCP ID | Target (module#export) | Input / state | Expect | Description |
|--------|------------------------|---------------|--------|-------------|
| `UCP-01` | `~/lib/filter#byGenre` | `items: […], genre: 'x'` | `toHaveLength(2)` | returns matching items |
| `UCP-02` | `~/lib/filter#byGenre` | `items: [], genre: 'x'` | `toEqual([])` | empty list in, empty list out |

- `Target` = exact import specifier + `#` + export name → becomes the plan's `Interfaces: Produces`
- `Expect` = a literal matcher expression (`toBe`, `toEqual`, `toHaveLength`, `toThrow`, `resolves.toEqual` …); do not invent vocabulary
- expected values are **hand-computed literals**, never derived by re-running the code under test — those pass whatever the code does
- UCP ids run across the whole tc.md (`UCP-01` …), not per TC, so `it` names never collide in a shared test file. If the sibling test file already has `UCP-NN` names, continue after its highest number
- unit test names follow `it('UCP-NN: <description>')` — the exact `--test` target of `red-gate.mjs`

Never add `Unit` or similar to the checkpoint `Type` list: the spec assembler stops on an unknown type. This separate sub-section is harmless to the batch parser.

## Entry-path DSL

| Step | Meaning |
|---|---|
| `goto('<url>')` | navigate, wait for `domcontentloaded` |
| `waitForAppReady()` | `adapter.waitForAppReady` with the TC's render-ready condition |
| `click(<target>)` | `adapter.locator(target).click()` |
| `fill(<target>, '<text>')` | type into an input |
| `press('<KEY>')` | one logical key through `adapter.press` |
| `waitFor: <expr or css> / { timeout: <ms> }` | wait for a condition |
| `loop press('<KEY>') × max N: <expr> → break` | state-based loop; **fixed repeat counts are not allowed**. Also for screens that drop keys behind a guard the spec cannot see (a flag set during a transition): `<expr>` is what shows the key took effect |
| `findAndEnter(<target>)` | goal-directed activation through the adapter |

`<target>` uses the same descriptor forms as DOM checkpoints. Keys are logical names (`Enter`, `ArrowDown`, `Escape`, …) the adapter maps.

## File-level trailing sections

Batch parsers ignore these; `coverage-gate` and `tdd-implement` read them.

### `## Manual review items` *(when any TC is `manual`)*

| TC ID | Name | Exclusion reason | Manual checkpoint |
|-------|------|------------------|-------------------|

If a manual TC has a `Unit target`, add `unit-verified` to the reason so reviewers do not duplicate what the runner covers.

### `## Implementation surface` *(new mode only)*

| Planned path | Kind | Nearest sibling | Sibling convention | Sibling test | Registration | Mocks needed | TCs |
|--------------|------|-----------------|--------------------|--------------|--------------|--------------|-----|
| `src/lib/filter.js` (new) | module | `src/lib/sort.js` | — | `src/lib/sort.test.js` | `src/lib/index.js` | (none) | TC-01 |
| `src/controller/NavController.js` | controller (a `case` added to `switch (target)`) | same file `#openDetail` | every case checks login first · passes `query.from` when it navigates | (none) | not needed | (none) | TC-03 |

Every path was confirmed on disk or is explicitly `(new)`; `coverage-gate --tc --lint` reports each row without `(new)` whose file does not exist. `tdd-implement` fills the plan's `Files:` and `Interfaces:` from this table.

`Sibling convention` cannot be empty on a row that modifies an existing file (`coverage-gate --tc --lint`): write what the sibling branches at the insertion point all do. A `(new)` file names the existing interpreter it reuses, or `—`.

### `## Entry branches` *(conditional)*

When sibling branches in a file being modified split on an entry flag (`isFrom…`), state what each new branch does for that flag. A branch the flag does not affect is `no split — <reason>`. Handing the landing to other code that reads the same input silently drops the entry information. `coverage-gate --tc --lint` finds the flags in the modified files and blocks any missing from this table.

| Flag (sibling location) | New branch | Handling |
|---|---|---|
| `isFromMenu` (`NavController.js` `#openA`) | b | passes `from: 'menu'` like `#openA` |
| `isFromMenu` (`NavController.js` `#openA`) | c | no split — sibling `#openC` ignores the flag too |

### `## Flag side effects` *(conditional)*

When a file being modified sets a shared flag (`obj.flag = true|false`) that other files read in `if (obj.flag) { … }` and write other state inside, list it here. `node <plugin>/scripts/flag-effects.mjs <file>...` produces the list. A flag kept true longer runs those writes longer and more often; restoring the flag alone leaves the state they changed. Per row, say whether this design changes how long the flag stays true and, if so, how the written value is restored. `coverage-gate --tc --lint` builds the same list and blocks a row missing the flag or the written name.

| Flag | Written while true | Handling |
|---|---|---|
| `inputLock` | `Panel.vue keyDownHandler` → `isReady` | this design holds the lock longer — restore `isReady` when releasing it |
| `isClosing` | `App.vue` → `opacity` | unchanged — this design does not touch `isClosing` |

### `## Input field interpretation` *(conditional)*

When a field named in the PRD's requirements or ACs (`snake_case`, `camelCase`) is split and read slot by slot by existing code, add a row per new branch that takes it. `node <plugin>/scripts/field-consumers.mjs <field>...` reports each interpreter (`fn`) and the slots it reads (`parsers[].segments`). Several branches taking the same field go side by side so different slot use is visible at G2.

- `Followed interpreter`: the existing function whose conversion and meaning the branch follows; `none — <reason>` if it follows none
- `Used slots` · `Dropped slots`: every slot the followed interpreter reads appears in one of the two — used slots with their use, dropped slots as `[n] — <reason>`

`coverage-gate --tc --lint` builds the same list and blocks a missing field row, an interpreter slot in neither column, or a dropped slot without a reason.

| Field | New branch | Followed interpreter | Used slots | Dropped slots |
|---|---|---|---|---|
| `item_path` | a | `openItem` | `[0]` code table → screen type · `[1]` group id · `[2]` item id | — |
| `item_path` | b | `openItem` | `[0]` code table → screen type · `[2]` item id | `[1]` — screen b takes the item id only |
| `item_path` | c | none — c passes `item_path` through as a URL | — | — |

### `## Implementation owners` *(new mode only)*

One row per TC whose `Unit target` is `(none)`. `coverage-gate` blocks a missing owner row at G2; `tdd-implement` turns `implement` rows into wiring tasks.

| TC | Owner | Reason |
|----|-------|--------|
| TC-11 | implement | wiring — fetch the remaining count on entry and render it |
| TC-17 | existing | the shared template already does this — regression check only |
| TC-24 | split PROJ-999 | entry path not reachable yet |

Owner values are exactly `implement`, `existing`, or `split <issue key>`.

### `## AC exclusions` *(only when an AC was excluded at review)*

| AC | Reason |
|----|--------|
| AC-07 | out of scope for this release — tracked in PROJ-123 |

An AC listed here is reported as `excluded` by `coverage-gate` instead of `uncovered` / `missing`. The first cell holds the `AC-NN` id; the reason is required.

## Priority and type rules

| Priority | Rule |
|---|---|
| High | core flow, directly maps an AC, failure blocks the feature |
| Medium | secondary behaviour, error handling |
| Low | regression, boundary, fine tuning |

| Type | Meaning |
|---|---|
| happy path | intended behaviour |
| error handling | API errors, empty data, network failure |
| ui | visibility, focus, layout |
| boundary | min/max, 0/1 items, timeouts |
| regression | adjacent existing behaviour still works |
