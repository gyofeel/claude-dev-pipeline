# PRD file format

Shared standard: `tc-extract` parses this format 1:1. Section headers (`##` / `###`) and table columns are parse keys — keep them exact. Optional sections are omitted entirely when empty (never left as a bare header).

## Header

```markdown
# <Feature name> PRD

> **Created**: YYYY-MM-DD
> **Scope**: <target screen > component>
> **Coverage**: Server[✅/⚠️Pass/—] · Platform[✅/⚠️Pass/—] · UI[✅/⚠️Pass/—] · Design[✅/⚠️Pass/—]
> **Sources**: <paths/links or none>
> **Open questions**: N (→ `## Open Questions`)
> **Generated by**: /dev-pipeline:prd-extract
```

`Platform` appears only when `platformInterface.enabled` is true in the config; otherwise the coverage line has three entries.

## `## Overview`

2–4 sentences: background, target users, main change.

## `## Requirements`

Numbered list. Each item describes one behaviour from the implementation point of view.

## `## Acceptance Criteria`

Checkbox list with ids `AC-01`, `AC-02`, … `tc-extract` maps each AC to at least one TC. **Do not append sources inline** (it pollutes parsing); put provenance in the table below.

```markdown
## Acceptance Criteria

- [ ] **AC-01**: <verifiable condition>
- [ ] **AC-02**: <verifiable condition>

### AC provenance

| AC ID | Source | Kind |
|-------|--------|------|
| AC-01 | Requirement 2 / ticket text / screen flow | stated / inferred |
```

## `## Server Interface` *(omit if none)*

```markdown
## Server Interface

### Endpoints

| Method | Path | Role |
|--------|------|------|
| GET | /api/<path> | <role> |

### Fixture mapping

| URL pattern | Fixture file | Status |
|-------------|--------------|--------|
| **/api/<path> | <name>.json | ✅ exists / 🆕 needed |

### Error cases

| Code | Description | TC candidate |
|------|-------------|--------------|
| <code> | <description> | ✅ / — |

### Boundary cases

- <empty list, max values, pagination, timeout …>
```

Fixture file names are checked against `e2e.fixturesDir` by the `fixture-advisor` agent before the PRD is saved.

## `## Platform Interface` *(only when enabled in config; omit if none)*

```markdown
## Platform Interface

### Mechanism

<how the web app talks to the host: bridge object, postMessage, SDK …>

### Events / callbacks

| Name | Parameters | App behaviour | Reproducible in E2E |
|------|------------|---------------|---------------------|
| <name> | <params> | <behaviour> | yes (page.evaluate mock) / manual only |

### Platform differences

<none, or details>
```

## `## UI Scenarios` *(omit if none)*

```markdown
## UI Scenarios

### Screen states

| State | Entry condition | Visible elements |
|-------|-----------------|------------------|

### Interaction sequences

| Scenario | Start URL | Steps |
|----------|-----------|-------|
| <name> | <url> | click "Movies" tab → select first card → … |

### Error / edge screens

| Case | Condition | Shown |
|------|-----------|-------|
```

Steps are written in plain interaction language (click, type, press KEY, wait for …). `tc-extract` turns them into the entry-path DSL.

## `## Design Guide` *(omit if none)*

```markdown
## Design Guide

### Components

| Component | Hook (testid / class) | States |
|-----------|-----------------------|--------|
| <name> | `data-testid="…"` or `.class` | normal / focus / disabled |

### Selector hints

| Hook | Meaning | Applies when |
|------|---------|--------------|

### Manual review items

| Item | Reason |
|------|--------|
| <item> | visual comparison / real device / … |
```

## `## Exceptions` *(omit if none)*

```markdown
- <case>: <condition> → <behaviour>
```

## `## Open Questions` *(omit if none)*

Every `Pass`, unclear, or inferred item ends up here. **Nothing is silently dropped.**

```markdown
| Item | Status | Reason | Follow-up |
|------|--------|--------|-----------|
| <item> | resolved / unclear / inferred / passed | <why, or the evidence when resolved> | tc-extract will check / product owner / platform team / developer / real device |
```

## `## Sources` *(omit if none)*

```markdown
- Ticket: <excerpt or scratch path>
- Interface specs: <paths/links>
- Figma / screenshots: <urls or attachment refs>
```

## Consumption map (how tc-extract uses each section)

| PRD section | tc-extract use |
|---|---|
| `## Acceptance Criteria` | Step 4c — one TC per AC minimum |
| `## Server Interface` → Fixture mapping | TC metadata `Fixtures` row / `page.route` mocks |
| `## Server Interface` → Error / Boundary | interface-coverage TCs |
| `## Platform Interface` → Reproducible in E2E | Step 4b E2E suitability |
| `## UI Scenarios` → Screen states | UI-flow coverage TCs |
| `## UI Scenarios` → Interaction sequences | `#### Entry path` |
| `## Design Guide` → hooks | `#### Checkpoints` DOM targets |
| `## Open Questions` | Step 3.5 uncertain items / manual review requests |
