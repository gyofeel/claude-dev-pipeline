# Failure routing table

Every value comes from `red-gate.mjs` output: `failureClass`, `routeTo`, `consumesFixRound`. The controller applies the row; it never classifies on its own. `OK_RED` · `OK_GREEN` · `OK_CHAR` have `routeTo: null` — nothing to route.

| failureClass (`routeTo`) | Route | Fix round | Thrash prevented |
|---|---|---|---|
| `ENV` (`user:env`) | **User** — report only (run `commands.setup`, reinstall dependencies, restore file ownership, free the port). No auto-install, no `sudo` | **not consumed** | "fixing" healthy tests because the environment is broken |
| `NOT_COLLECTED` (`controller:placement`) | **Controller** — move the test file to a path matching `unitTest.testFileGlobs` and none of `excludedFilePatterns`, or pass the `--project` that collects it. Never edit the runner config without explicit user approval | no | an implementer reading `0 failed` as green; several implementers each widening the glob |
| `SKIPPED` (`controller:placement`) | **Controller** — check that `--project` (or `unitTest.runnerArgs`) selects the project that collects this file, and that no `it.skip` / `it.todo` / stray `.only` remains. **Do not touch production code** | no | reading a test that never ran as "passed at RED" and deleting working code |
| `GREEN_WITHOUT_RED` (`controller:halt`) | **Controller — stop.** If this task's production code was written first, **delete it (do not adapt it)** and restart from RED. If the previous task's implementation already makes the test pass, the plan is wrong: move the test to that task, or turn it into a `**characterization**` task (`--phase char`) when it pins existing behaviour | no (a rule violation, not a bug) | the #1 TDD-agent failure: implement → write a passing test → report DONE. **Indistinguishable from real TDD in the final diff** |
| `NO_RED_ON_RECORD` (`controller:halt`) | **Controller — stop.** No RED or characterization record for this test: RED was skipped, or `--file` / `--test` differ from the RED run. Run `--phase red` with the same arguments first | no | a GREEN claim with no evidence that the test ever failed |
| `GATE_ERROR` (`controller:halt`) | **Controller — stop.** The gate itself could not run (missing argument, relative `--file`, `char` without the marker). Fix the command, not the code | no | treating a broken gate call as a verdict |
| `WRONG_REASON{module}` (`implementer:test-only`) | **Implementer, test file only** — module-level failure (import, module-scope state, syntax). A missing new module listed under the plan's `Create:` is already `OK_RED`, so what lands here is a path typo or a missing `Create:` line | consumed | papering over a broken test with production code; creating a stub first to fake a RED |
| `WRONG_REASON` / `WRONG_REASON_UNKNOWN` (`implementer:test-only`) | **Implementer, test file only** (no production code this round). `is not a function` for a new export listed under `Produces` is already `OK_RED`; one that lands here is a missing mock or a missing `Produces` line | consumed | same |
| `WRONG_REASON` timeout on the same `(file, test)` **twice in a row** (ledger lookup) | **User — stop.** "This check appears to exceed the unit-test boundary. Set this TC's `Unit target` to `(none)` and hand it to E2E?" | no | burning every fix round on something in `unitTest.excludedAreas` |
| `TARGET_NOT_FOUND` / `TARGET_AMBIGUOUS` (`implementer:test-only`) | Implementer — make the `it('UCP-NN: …')` name and `--test` match | consumed | — |
| `STILL_RED` (`implementer`) | Implementer — normal SDD fix round (attach `subClass`) | consumed | — |
| `COLLATERAL_RED` (`implementer`), failing test **inside** the plan's `Files:` | Implementer — name the failing test | consumed | — |
| `COLLATERAL_RED`, failing test **outside** the plan's `Files:` | **User — stop.** Shared code outside the declared surface was touched | no | the two worst agent "repairs": fixing pre-existing failures it did not cause, deleting failing tests |
| `RUN_INCOMPLETE` (`controller:rerun`) | **Controller** — run it again. With `--all`: the suite did not finish; a file-level error repeating in the same file goes to the implementer of the task that changed that file. On a per-task red / green / char run: the target passed but the run did not finish cleanly (file-level error, unfinished tests, non-zero exit without failures) — rerun, and if it repeats read `stderrTail` and fix the cause | no | reading zero failures as a pass: if the run did not finish, regression is unknown |
| pre-commit hook blocked (formatter or lint) | Implementer — run `commands.format`, commit again. **Never `--no-verify`** | no | hook bypass piling up format debt |
| TC / PRD contradictory or insufficient | Do not stop. Implement what the PRD says, and record it in the report's `upstream conflict` line and as a Ruling. Rewinding is the human's call at G3 | no | implementing imagined requirements; a dropped requirement left in the docs and flagged as unimplemented next round |
| code and a PRD spec value (URL, key basis, field) differ | Leave the conflicting existing code alone; put the spec source in `upstream conflict`. A human checks the original at G3 | no | "fixing" correct code to match a PRD that mis-copied the spec |

Cost tiers: deterministic gates run as direct Bash (no LLM re-spawn); per-task green runs one file; the full suite (`--all`) runs once at the final gate.
